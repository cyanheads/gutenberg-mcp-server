# 0.3.1 — 2026-10-30

## Added

- **`gutenberg_get_text` `find`** ([#35](https://github.com/cyanheads/gutenberg-mcp-server/issues/35)): returns the chunk starting at the first match at or after `offset`, with `match` (`offset`, `length`, `laterMatches`). It searches one book, ignoring letter case, whitespace runs, and straight versus curly quotes. A missing passage fails with `passage_not_found`.
- **`gutenberg_search_books` `translator`** ([#34](https://github.com/cyanheads/gutenberg-mcp-server/issues/34)): every word must occur in a translator name, accents included. It needs the local mirror and otherwise fails with `translator_requires_mirror`. Result rows still omit translators; `gutenberg_get_book` reports them.
- **Mirror schema v4**: a `translators_folded` column, backfilled in place on first open of an existing mirror, without a harvest.

## Changed

- `gutenberg_get_text` offsets on HTML-only editions move, because whitespace-only lines no longer count: an offset saved from an earlier release can land elsewhere in the text, and one at or past the new `totalChars` fails `offset_out_of_range`.
- `gutenberg_search_books` with both author-year bounds returns fewer books, so a page number saved from an earlier release can fail `page_out_of_range`.
- **Server instructions** mention `find` and say that a backslash before punctuation in `content[]`, outside code spans and fences, is Markdown encoding.
- **`gutenberg-guide` skill** 1.0 → 1.1: covers `find`, `translator`, one-author year bounds, and exact language codes.

## Fixed

- **HTML-edition text** ([#32](https://github.com/cyanheads/gutenberg-mcp-server/issues/32), [#39](https://github.com/cyanheads/gutenberg-mcp-server/issues/39)): lines holding only whitespace are emptied, and a table row reads on one line with tab-separated cells, whatever the source indentation. Plain-text editions are byte-identical to 0.3.0.
- **Author-year bounds** ([#36](https://github.com/cyanheads/gutenberg-mcp-server/issues/36)): with both `author_year_start` and `author_year_end`, one author must meet both, as the tool description says. A single bound is unchanged. The live catalog cannot check this: it checks the two bounds separately and says so in `notice`.
- **`content[]` Markdown** ([#31](https://github.com/cyanheads/gutenberg-mcp-server/issues/31), [#37](https://github.com/cyanheads/gutenberg-mcp-server/issues/37)): titles, names, languages, subjects, bookshelves, summaries, and provenance are escaped. The `Search criteria` and `Browse criteria` echoes and the browse continuation arguments sit in code spans. `gutenberg_get_book` puts source notes in a fenced block and renders each format as a link. A CommonMark parse now reads back what `structuredContent` carries.
- **Language codes** ([#38](https://github.com/cyanheads/gutenberg-mcp-server/issues/38)): `languages` on `gutenberg_search_books` and `gutenberg_browse_popular` accepts two- or three-letter catalog codes. `enm` and `ang` were rejected and now match books; `["eng"]` was rejected and is now an empty success with a notice naming `en`.
