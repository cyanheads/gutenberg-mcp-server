# 0.2.0 — 2026-10-17

## Added

- **Discovery filters** add optional MIME-prefix and tri-state copyright selection to search and browse, including criteria echo and continuation arguments ([#28](https://github.com/cyanheads/gutenberg-mcp-server/issues/28)).
- **Discovery context** exposes normalized criteria, empty-result notices and executable browse continuation in text and structured output ([#25](https://github.com/cyanheads/gutenberg-mcp-server/issues/25)).

## Changed

- **Catalog discovery** uses the ready local mirror, applying every query word and combined filters before counts, ordering and pagination; existing databases receive a bounded search-column backfill without reharvesting ([#2](https://github.com/cyanheads/gutenberg-mcp-server/issues/2)).
- **Empty discoveries** from `gutenberg_search_books` and `gutenberg_browse_popular` succeed with zero matches, the normalized criteria and a notice; the `no_results` error reason is removed ([#20](https://github.com/cyanheads/gutenberg-mcp-server/issues/20)).
- **Live fallback**: Reject queries longer than four words when the catalog mirror cannot answer, with query_requires_mirror recovery guidance ([#19](https://github.com/cyanheads/gutenberg-mcp-server/issues/19)).

## Fixed

- **Empty ID selections** return zero matches without catalog I/O ([#20](https://github.com/cyanheads/gutenberg-mcp-server/issues/20)).
- **Live catalog attempts** use the remaining 15-second budget instead of restarting a still-running request after five seconds, preserving cancellation and transient retries ([#15](https://github.com/cyanheads/gutenberg-mcp-server/issues/15)).
- **Mirror lifecycle commands** fix compiled-module resolution in npm packages and MCPB bundles; Docker uses the same runtime aliases. README documents mirror initialization and persistence.
